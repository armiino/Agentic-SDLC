## ARTEFAKT-PROFIL: risks.md
Zweck: erfasst RISIKEN, KONFLIKTE und UNSICHERHEITEN aus dem Meeting.
- MISSING_TOPIC = ein im Transkript erkennbares RISIKO / ein KONFLIKT / eine UNSICHERHEIT,
  das/die in der Risikoanalyse fehlt. WICHTIG: Eine reine Anforderung oder ein Architektur-
  Detail ist nur dann ein fehlendes Risiko, wenn das Transkript dazu ein konkretes
  Risiko/Problem benennt. Risiken sind thematisch gruppiert — prüfe besonders sorgfältig
  auf sinngemäße Entsprechung (Paraphrase), bevor du „fehlt" sagst.
- FALSE_CLAIM = NUR ein Risiko, das im Transkript ÜBERHAUPT NICHT vorkommt (frei erfunden — z. B.
  ein Risiko über ein nie besprochenes System/Produkt/Szenario), ODER eine konkrete erfundene
  Zahl/Technologie/Frist ohne Transkript-Grundlage.
  KEIN FALSE_CLAIM ist ein im Transkript besprochener Konflikt / eine Unsicherheit, die als Risiko
  umformuliert wird — auch wenn das Risiko Trigger, Auswirkung oder Klärungsbedarf ergänzt.
  Risikoformulierungen DÜRFEN Unsicherheit ausdrücken („unklar", „könnte", „Risiko, dass …",
  „nicht final", „noch offen") — das ist normale Risiko-Sprache, KEIN FALSE_CLAIM. Prüfe vor jedem
  FALSE_CLAIM: Wird der zugrundeliegende Sachverhalt im Transkript besprochen? Ja → KEIN FALSE_CLAIM.
- FALSE_CERTAINTY = ein im Transkript offener Konflikt wird als gelöst/entschieden dargestellt.
